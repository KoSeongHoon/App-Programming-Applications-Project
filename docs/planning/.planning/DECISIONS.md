### **결정 1: MVP 스코프 확정**

**일시**: 2026-05-18 (세션 1)  
**결정자**: 고성훈  
**상태**: ✅ 확정

#### 결정 내용
프로젝트의 MVP(최소 기능 제품) 범위를 다음과 같이 확정:
- ✅ 타임라인 기반 주간 콘텐츠 자동 감지
- ✅ 체크리스트 형식의 플래너 UI
- ❌ 강화 계획 모듈 (추후)
- ❌ 능력치 대시보드 (추후)
- ❌ 아바타 강화 (추후)

#### 이유
- 6주 일정이 촉박하므로 코어 기능에 집중
- "타임라인 → 자동 감지 → 체크" 플로우가 가장 핵심 가치
- 강화 계획은 추후 BONUS로 추가 가능

#### 영향도
- 개발 시간: -5~7일 절감
- 완성도: MVP 달성 가능성 높음
- 추후 확장: BONUS 기능으로 대체

#### 관련 문서
- `.planning/01-requirements.md` (MoSCoW 분류)
- `BONUS.md` (추후 기능)

### **결정 2: 서버 범위 → 한국만 (초기)**

**일시**: 2026-05-18 (세션 1)  
**결정자**: 고성훈  
**상태**: ✅ 확정

#### 결정 내용
Neople API 캐릭터 검색 시 **한국 서버만 지원**

#### 대안 검토
| 옵션 | 장점 | 단점 |
|------|------|------|
| A) 한국만 (선택) | 구현 간단, 속도 빠름 | 확장성 제한 |
| B) 다중 서버 | 확장성 좋음 | 복잡도 증가, 시간 소요 |

#### 이유
- MVP에서는 단순성 우선 (YAGNI)
- 한국 서버만 집중하면 개발 시간 -2~3일
- 추후 멀티 서버는 BONUS로 추가 가능

#### 영향도
- 개발: 서버 선택 UI 제거 가능
- 테스트: 테스트 케이스 감소
- 기능: 한국 플레이어만 사용 가능 (초기)

#### 관련 문서
- `SPECS.md` (서버 목록)
- `BONUS.md` (향후 멀티 서버)

### **결정 3: 콘텐츠 범위 → 일일 + 주간**

**일시**: 2026-05-18 (세션 1)  
**결정자**: 고성훈  
**상태**: ✅ 확정

#### 결정 내용
플래너에서 추적할 콘텐츠 범위:
- ✅ 일일 콘텐츠 (하루 1회 가능)
- ✅ 주간 콘텐츠 (주 1회 제한)
- ❌ 필드 보스, 이벤트 등 (제외)

#### 대안 검토
| 옵션 | 범위 |
|------|------|
| A) 일일만 | 던전, 일일 레이드 |
| B) 일일 + 주간 (선택) | 위 + 주간 던전, 주간 특별 |
| C) 모든 콘텐츠 | 위 + 필드보스, 이벤트 |

#### 이유
- B가 가장 실용적 (대부분의 유저가 추적)
- C는 데이터 관리 복잡도 증가
- 주간 콘텐츠까지 포함하면 플래너 가치 극대화

#### 영향도
- 카탈로그 규모: 20~30개 항목
- UI 복잡도: 중간 수준
- 사용자 만족도: 높음

#### 관련 문서
- `.planning/01-requirements.md` (시나리오)
- `SPECS.md` (콘텐츠 정의)

### **결정 4: 플래너 UI → 체크리스트 형식**

**일시**: 2026-05-18 (세션 1)  
**결정자**: 고성훈  
**상태**: ✅ 확정

#### 결정 내용
플래너 UI를 **체크리스트 형식**으로 구현

#### 대안 검토
| 옵션 | UI 형식 |
|------|--------|
| A) 체크리스트 (선택) | ☐ 던전명 / ☑ 클리어 |
| B) 진행도 바 | ████░░░░ (5/10 클리어) |
| C) 카드 형식 | 각 콘텐츠별 상세 카드 |

#### 이유
- A가 가장 간단하고 직관적
- 빠른 인지 가능 (한눈에 파악)
- 개발 난이도 낮음
- 진행도 바는 추가로 표시 가능

#### 영향도
- 개발 시간: 1.5일
- UI/UX: 매우 직관적
- 수동 조정: 체크박스 클릭으로 간단

#### 관련 문서
- `.planning/01-requirements.md` (시나리오 3)
- `.planning/04-schedule.md` (일정)

### **결정 5: 피로도 기능 → 제외**

**일시**: 2026-05-18 (세션 1)  
**결정자**: 고성훈  
**상태**: ✅ 확정

#### 결정 내용
Neople API에서 피로도 정보를 제공하지 않으므로 **MVP에서 제외**

#### 대안 검토
| 옵션 | 설명 |
|------|------|
| A) 제외 (선택) | 피로도 기능 없음 |
| B) 수동 입력 | 사용자가 직접 입력 |
| C) 웹 스크래핑 | 이용약관 위반 위험 |

#### 이유
- API 미지원이므로 A 또는 B만 가능
- A가 더 간단하고 MVP 범위 유지
- B는 BONUS로 추후 추가 가능
- C는 법적 위험

#### 영향도
- 개발: 시간 절감 (구현 불필요)
- 기능: 피로도 추적 미지원 (초기)
- 확장: BONUS에서 추가 가능

#### 관련 문서
- `.planning/01-requirements.md` (Won't)
- `BONUS.md` (향후 기능)
