### **[슬라이드 2] 기획: 문제 정의 & 솔루션 (45초)**

```
현재 던파 플레이어들이 겪는 문제는 3가지입니다.

첫째, 주간 컨텐츠 관리가 복잡합니다.
상급던전, 레기온, 레이드 등 7개의 컨텐츠를
매주 관리해야 하는데요,

둘째, 반복적인 확인 작업이 번거롭습니다.
매주 목요일마다 초기화되는 컨텐츠를
매번 일일이 확인해야 합니다.

셋째, 여러 캐릭터를 운영하는 사용자들은
각 캐릭터의 클리어 상태를 추적하기 어렵습니다.

이 모든 문제의 솔루션이 바로 우리 앱입니다!

[강조하며] 한 앱에서 모든 캐릭터의 주간 컨텐츠 
클리어 현황을 한눈에 확인하고 관리할 수 있습니다.
```

**[슬라이드 2에서 마무리 후 "다음" 클릭]**

### **[슬라이드 3] 설계: 아키텍쳐 & 기술 스택 (45초)**

```
이제 앱의 설계에 대해 설명하겠습니다.

[다이어그램 가리키며]
우리는 Clean Architecture의 4계층 구조를 사용했습니다.

최상단의 Presentation Layer에서는
홈 화면에서 캐릭터를 검색하고,
플래너 화면에서 컨텐츠를 관리합니다.

Application Layer의 ViewModel에서는
비즈니스 로직을 처리하고,

Domain Layer의 Entity에서는
데이터 구조를 정의합니다.

마지막으로 Data Layer에서는
Neople API에서 타임라인 데이터를 받아오고,
SQLite 데이터베이스에 저장합니다.

기술 스택은 다음과 같습니다:
- 프론트엔드: Flutter 3.41.9
- 상태 관리: Riverpod
- 데이터베이스: SQLite
- API: Neople 던파 API

이러한 구조로 확장성 있고 유지보수하기 쉬운
앱을 만들었습니다.
```

**[슬라이드 3에서 마무리 후 "다음" 클릭]**

기획 및 설계 단계는 100% 완료했고,

개발 단계는 85% 진행 중입니다:
- UI 구현: 완료
- 캐릭터 검색: 완료
- 타임라인 파싱: 90% 진행 중
- 컨텐츠 추적: 80% 진행 중

앞으로는 타임라인 파싱을 완성하여
컨텐츠 클리어 상태를 정확하게 추적하고,
단위 테스트와 통합 테스트를 진행한 후
Play Store에 배포할 계획입니다.

감사합니다!
