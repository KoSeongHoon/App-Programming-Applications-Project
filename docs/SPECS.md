# SPECS.md — 던전앤파이터 플래너 도메인 규칙

이 프로젝트에 특정한 게임 도메인 지식, 데이터 규칙, 용어 정의를 정리합니다.

---

## 🎮 게임 용어 정의

### 캐릭터
| 용어 | 정의 | 예시 |
|------|------|------|
| **닉네임** | 캐릭터 이름 | "고성훈", "검은눈" |
| **직업** | 캐릭터의 직업 분류 | 검술사, 격투가, 마법사, 총잡이 등 |
| **레벨** | 캐릭터의 성장 단계 (1~110) | 110 |
| **경험치** | 현재 레벨의 진행도 (%) | 45% |

### 능력치
```
STR (힘)     : 물리 공격력
DEX (민첩)   : 정확도, 회피율
VIT (체력)   : 생명력
INT (지능)   : 마법 공격력
MEN (정신)   : 마법 방어
WIL (의지)   : 상태이상 저항
```

### 장비 강화
| 용어 | 정의 | 예시 |
|------|------|------|
| **강화도** | 장비의 강화 단계 (+0~+12) | +8 |
| **강화 성공율** | 강화 시도 시 성공 확률 | 80% |
| **강화석** | 강화에 필요한 재료 | 필수 재료 |
| **골드** | 게임 내 화폐 | 100,000,000 |

### 콘텐츠
| 분류 | 설명 | 특징 |
|------|------|------|
| **던전** | 스토리/일반/전설 던전 | 난이도별 분류 |
| **레이드** | 여러 플레이어 참여 | 주간 제한 |
| **이벤트** | 기간 제한 콘텐츠 | 임시 보상 |

## 🛠️ 기능별 도메인 규칙

### 1. 캐릭터 조회
- ✅ 닉네임은 필수 입력
- ✅ 서버별로 같은 닉네임 가능 → 서버 선택 필수
- ✅ 110레벨 이상만 타임라인 API 사용 가능
- ✅ API 응답 캐시: 1시간 (API 제한)

### 2. 장비 강화 계획
- ✅ 강화도 범위: +0 ~ +12
- ✅ 강화 확률 테이블: 게임 공식 데이터 사용
- ✅ 필요 재료:
  - 골드 (필수)
  - 강화석 (필수)
  - 추가 아이템 (강화도별)
- ✅ 계산 규칙:
  - 예상 비용 = (성공 시 비용 × 성공율) + (실패 시 손실 × 실패율)
  - 주간 쿠오타 = 일일 획득량 × 7

### 3. 아바타 강화 계획
- ✅ 아바타 강화도: +0 ~ +10
- ✅ 아바타 별 강화 레벨 상이
- ✅ 필요 재료: 금속/천/가죽 등 재료별 관리

### 4. 활동 기록 (타임라인)
- ✅ Neople 타임라인 API로 조회
- ✅ 최근 90일 데이터만 제공
- ✅ 타임라인 코드로 활동 필터링 가능
- ✅ 110레벨 이상만 조회 가능

## 🗄️ 데이터 저장 규칙

### 로컬 저장소 스키마
```sql
-- 캐릭터
CREATE TABLE characters (
  id INTEGER PRIMARY KEY,
  characterId TEXT UNIQUE,
  nickname TEXT,
  server TEXT,
  jobName TEXT,
  level INTEGER,
  createdAt TIMESTAMP,
  updatedAt TIMESTAMP
);

-- 장비 강화 계획
CREATE TABLE enhancement_plans (
  id INTEGER PRIMARY KEY,
  characterId TEXT,
  itemName TEXT,
  currentEnhancement INTEGER,
  targetEnhancement INTEGER,
  status TEXT, -- 'in_progress', 'completed', 'abandoned'
  createdAt TIMESTAMP,
  updatedAt TIMESTAMP,
  FOREIGN KEY (characterId) REFERENCES characters(characterId)
);

-- 강화 이력
CREATE TABLE enhancement_history (
  id INTEGER PRIMARY KEY,
  planId INTEGER,
  attemptDate TIMESTAMP,
  success BOOLEAN,
  cost INTEGER,
  createdAt TIMESTAMP,
  FOREIGN KEY (planId) REFERENCES enhancement_plans(id)
);
```
